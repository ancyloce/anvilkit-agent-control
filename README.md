# anvilkit-agent-control

The Control service of the AnvilKit Agent platform: admission, budgets, prices and single-use dispatch, execution and effect registries, the obligation inventory, scoped artifact transfer, accepted results, preparations, generations, previews and releases, the MCP grant policy, projections, the Temporal relay and the publication of operation events. It is the sole writer of the `anvilkit_control` database and the authority the API and the Workflow worker call over gRPC (`anvilkit.control.v1`). The architecture that owns this service is the parent repository `anvilkit-services` (`docs/architecture/`: the service catalog, `contracts.md` for the RPC groups, data ownership and lock ranks, `execution.md` DD-02 for admission, effects, inventory and artifacts); the parent mounts this repository as the submodule `services/agent/control`.

This repository holds the replacement implementation (grpc-go, Fx, pgx/v5 with sqlc-generated data access, goose/v3 migrations, koanf configuration, the AWS SDK v2 for the S3-compatible inventory and artifact backends, the Temporal client for the relay, watermill-sql and NATS JetStream for the event outbox). The previous implementation that lived here (Connect RPC, the retained contracts) is outside the build closure of the replacement and is not a starting point; its last worktree is preserved by the parent's cleanup record, not here.

## Layout

| --- | --- |

| `internal/adapters/{authority,evidence}` | The guarded client of the commercial authority decision endpoint the deployment declares, and the verifier of signed not-sent and disposition evidence |

| `internal/adapters/outbox` | The watermill-sql outbox on Control's transactions, its forwarder to NATS JetStream and the waker of the event streams |
| `internal/adapters/retention` | The deletion of expired operation events under the retention identity |
| `internal/migrate` | The service-owned migration source: `sql/00001_init.sql` and the forward migrations, the goose provider the Job and the tests use |
| `internal/testdb` | A disposable PostgreSQL 17 (Testcontainers) installed from `internal/migrate` for the tests |

| `deploy/chart` | The service's Helm chart (Deployment, Service, ServiceAccount, ConfigMap, PodDisruptionBudget, the migration Job as a pre-install/pre-upgrade hook, the cert-manager workload `Certificate`, an optional HorizontalPodAutoscaler, the CSI `SecretProviderClass` under `secrets.provider: csi`) |
| `Dockerfile`, `.dockerignore` | Image build from this repository root alone; the image carries the service and the migration binary |

Dependency direction: `cmd -> bootstrap(Fx) -> transport -> application -> domain`; adapters implement the application's ports. The generated contract (`github.com/ancyloce/anvilkit-agent-contracts/go`: `anvilkit/control/v1`, `jobschema`) is an ordinary versioned module requirement, resolved through GOPROXY. There is no replace directive, no workspace file and nothing read from a sibling checkout.

## Configuration

The service reads one reviewed, secret-free file (`config.yaml`, path from `ANVILKIT_CONTROL_CONFIG`, default `./config.yaml`) with the sections `development` (the top-level DEVELOPMENT_ONLY guard), `health` (the plaintext HTTP probe listener, `/healthz` and `/readyz`, and its database check), `telemetry`, `grpc` (listen, capacities, shutdown, the mTLS workload identity and its trust domain), `database` (the app-role pool), `inventory` (backend `filesystem` or `s3`), `artifacts` (backend `disabled` or `s3`, bounds), `temporal`, `relay`, `profiles`, `recovery`, `dispatch` (the authority, evidence and price inputs, reconciliation, and its file-only DEVELOPMENT_ONLY fixtures), `model_proxy` (the Model Proxy placement of the original-identity query of model dispatches, `internal/adapters/modelproxy`: with an address recovery asks the Proxy's `GET /api/v1/model-calls/{callId}` about an unresolved model dispatch of the configured owner and records the answer as an observation under the source `query:model-proxy`; without one the DEVELOPMENT_ONLY attestation double answers), `events` (the outbox forwarder to NATS JetStream and the waker) and `retention` (`internal/config/config.go`, `Config`). The only environment overrides are `ANVILKIT_CONTROL_LISTEN`, `ANVILKIT_CONTROL_HEALTH_LISTEN`, `ANVILKIT_CONTROL_IDENTITY_{CERT_FILE,KEY_FILE,CA_FILE,TRUST_DOMAIN}`, `ANVILKIT_CONTROL_TELEMETRY_{OTLP_ENDPOINT,METRICS_LISTEN}`, `ANVILKIT_CONTROL_TEMPORAL_ADDRESS`, `ANVILKIT_CONTROL_INVENTORY_DIR`, `ANVILKIT_CONTROL_INVENTORY_S3_{ENDPOINT,BUCKET,ACCESS_KEY_ID,SECRET_ACCESS_KEY}`, `ANVILKIT_CONTROL_ARTIFACTS_S3_{ENDPOINT,BUCKET,ACCESS_KEY_ID,SECRET_ACCESS_KEY}`, `ANVILKIT_CONTROL_MODEL_PROXY_ADDRESS`, the secret `ANVILKIT_CONTROL_MODEL_PROXY_TOKEN`, `ANVILKIT_CONTROL_AUTHORITY_{URL,TOKEN_FILE}`, `ANVILKIT_CONTROL_PRICES_INITIAL_FILE`, `ANVILKIT_CONTROL_NATS_{URL,CREDS_FILE}`, `ANVILKIT_CONTROL_NATS_TLS_{MODE,CA_FILE,CERT_FILE,KEY_FILE,SERVER_NAME}`, the secret `ANVILKIT_CONTROL_DATABASE_URL` and the secret `ANVILKIT_CONTROL_RETENTION_DATABASE_URL` (`envOverrides` in the same file); the two database URLs and the four S3 credentials also arrive as mounted secret files (`ANVILKIT_CONTROL_DATABASE_URL_FILE`, `ANVILKIT_CONTROL_RETENTION_DATABASE_URL_FILE`, `ANVILKIT_CONTROL_{INVENTORY,ARTIFACTS}_S3_{ACCESS_KEY_ID,SECRET_ACCESS_KEY}_FILE`, or the matching `*_file` keys; P0.6), read once at load and mutually exclusive with the value. Any other `ANVILKIT_CONTROL_*` variable stops the process, and a secret found in the file refuses the candidate. Outside `development.enabled` the DSN must name `sslmode=verify-full` and a selected S3 endpoint must be `https` (P0.6). The gRPC health service reports `SERVING` once the listener is up and the relay runs, `NOT_SERVING` while the server drains.

## Migrations

`internal/migrate/sql` is the migration source of `anvilkit_control` (`00001_init.sql` plus the forward migrations `00002` to `00019`; goose/v3, append-only). `anvilkit-migration (-dsn "$ANVILKIT_MIGRATION_DSN" | -dsn-file "$ANVILKIT_MIGRATION_DSN_FILE") [-development] [-to N] [-status]` applies them (exactly one DSN source; outside `-development`/`ANVILKIT_MIGRATION_DEVELOPMENT=true` the DSN must name `sslmode=verify-full`) with the migrator role (`anvilkit_control_migrator`); the runtime role (`anvilkit_control_app`) receives DML only and never deletes an operation event (`00018`). The retention identity (`anvilkit_control_retention`, `00019`, RB-A27) reads operations and deletes the event prefix of settled terminal operations unchanged for `retention.operation_events` (the data owner's period, ENV-09), keeping the newest attempt-bound event and every later one; Control runs it in process on its own one-connection pool (`ANVILKIT_CONTROL_RETENTION_DATABASE_URL` or `_FILE`, required outside development) and verifies each interval that it is neither the app role nor the table owner; a cursor before the kept events answers `RESET_REQUIRED`. The chart runs the same binary as a Job before the release's Pods roll. `internal/migrate/migrate_test.go` installs an empty PostgreSQL 17, checks the role boundary, the version, Down/Up and the forward migration of a stage accepted before `00002`.

## Deploy

`deploy/chart` carries only what this service needs. Required values: `database.secret.name` (an existing Secret with the application-role URL), `temporal.address`, the shared obligation inventory `inventory.s3.{endpoint,bucket,secret.name}` (every replica must use the same backend; the filesystem adapter is DEVELOPMENT_ONLY and is not rendered by the chart), the artifact store `artifacts.s3.{endpoint,bucket,secret.name}` unless `artifacts.enabled: false`, `migration.secret.name` (the migrator-role URL) unless `migration.enabled: false`, and outside development the retention identity, `retention.secret.name` (or `retention.enabled` under CSI, key `retention-database-url`), with its period `retention.operationEvents` (RB-A27). Operation events (P2.8): `events.enabled` (the default) is required outside development and needs the JetStream placement `events.nats.url`; under `events.nats.tls.mode` `tls` or `mtls` (the default is `tls`; `mtls` needs `identity.mode: mtls`) `events.nats.tls.caSecret.name`, and under `secrets.provider: kubernetes` `events.nats.credentials.secret.name` (under CSI the key `nats-creds`) unless the mode is `development` (DEVELOPMENT_ONLY). Under `identity.mode: mtls` (the default) the workload identity needs `identity.trustDomain` outside development and `identity.certificate.issuerRef.name` (or `identity.certificate.create: false` with `identity.secretName`); under `temporal.tls.mode` `tls` or `mtls` (the default is `tls`) `temporal.tls.caSecret.name`; outside `config.dispatch.development` (off by default) the production admission inputs `authority.url`, `evidence.issuers` with `evidence.configMap`, and `modelProxy.address` (plus `modelProxy.tokenSecret.name` under `modelProxy.identityMode: development`); under `secrets.provider: csi` `secrets.csi.address` and `secrets.csi.path` (and `secrets.csi.migrationPath` while the migration Job is enabled). The chart never creates Secrets. `image.digest` pins the exact image and is required outside development (a tag renders only with `development.enabled`); `config` renders the reviewed file into a ConfigMap; `resources`, HTTP probes on the health listener (`/readyz` for startup and readiness, `/healthz` for liveness), the security context and a PodDisruptionBudget are declared — the budget selects the runtime Pods by their `app.kubernetes.io/component: control` label (a Pod-template label, not part of the Deployment's immutable selector), so the migration Job's Pods, which share the selector labels under component `migration`, are neither counted nor held back by it. Environment values (addresses, buckets, replica counts, digests, Secret names) and the pinned deployment combination belong to the deploying repository (`anvilkit-services`, `deploy/dev` for the development foundation), never to this chart. Plaintext gRPC and the DEVELOPMENT_ONLY fixtures are development inputs; runtime qualification (the parent's G gates) is not claimed by any check here.
